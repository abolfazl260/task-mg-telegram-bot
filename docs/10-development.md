# راهنمای توسعه

## اضافه کردن قابلیت جدید

برای قابلیت جدید ترجیحاً این تفکیک حفظ شود:

```text
Handler
  ↓
Service
  ↓
Database / External API
  ↓
UI / Response
```

## افزودن فیلتر به `/tasks`

```text
tasks_view_menu_keyboard
↓
callback
↓
query
↓
filter
↓
render
```

فیلتر باید تا حد امکان با Query دیتابیس انجام شود و از بارگذاری غیرضروری همه Taskها جلوگیری شود.

## تست

پیش از ارسال تغییرات:

```bash
pytest
```

برای تغییرات مرتبط با دیتابیس، تست Migration و Schema نیز باید اجرا شود.

## مستندات

هر قابلیت مهم جدید باید همراه با مستندات مناسب در `docs/` اضافه یا مستندات موجود در همان بخش به‌روزرسانی شود.

README ریشه فقط باید نقش صفحه ورود و Navigation را داشته باشد؛ جزئیات پیاده‌سازی و راهنمایی‌های طولانی باید در `docs/` قرار بگیرند.

## Pull Request

عنوان و توضیح PR باید مشخص کند:

- چه چیزی تغییر کرده است.
- چرا تغییر لازم بوده است.
- آیا Schema یا Migration تغییر کرده است.
- آیا تنظیمات محیطی جدید لازم است.
- چه تست‌هایی اجرا شده‌اند.
