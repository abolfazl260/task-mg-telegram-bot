# مسیر خرید مشتری — Buyer Journey

> بازار اولیه: کلینیک خصوصی دندان‌پزشکی چندپزشکه  
> هدف: تعریف مسیر از «احساس مشکل» تا «Renewal و Expansion» و مشخص‌کردن کار Product/Sales/Marketing در هر مرحله.

---

# 1. خلاصه Journey

مسیر خرید این محصول معمولاً self-serve ساده نیست. Buyer باید:

1. وجود مشکل عملیاتی را بپذیرد؛
2. هزینه روش فعلی را درک کند؛
3. متقاعد شود نرم‌افزار فعلی کلینیک به‌تنهایی این مشکل را حل نمی‌کند؛
4. ببیند TaskMG جایگزین اجباری PMS/EMR نیست؛
5. مطمئن شود frontline واقعاً استفاده می‌کند؛
6. امنیت و privacy را بپذیرد؛
7. در Pilot نتیجه قابل اندازه‌گیری ببیند.

بنابراین Sales Motion پیشنهادی:

**Consultative Sale → Workflow Discovery → Targeted Demo → Limited Pilot → Paid Conversion**

# 2. Buying Committee

## Economic Buyer
مالک یا شریک اصلی.

## Champion
مدیر داخلی، operations manager یا coordinator.

## Daily User
پذیرش، follow-up staff، assistant.

## Clinical Influencer
پزشک/دندان‌پزشک.

## Technical / Compliance Influencer
IT، مشاور نرم‌افزار یا مسئول privacy در مجموعه بزرگ‌تر.

## Potential Blocker
کاربری که سیستم را «کنترل کارکنان» یا «data entry اضافه» می‌بیند.

# 3. Stage 0 — Latent Pain

## وضعیت مشتری
مشکل وجود دارد ولی هنوز «نیاز به نرم‌افزار جدید» تعریف نشده.

## نشانه‌ها
- گروه پیام‌رسان شلوغ؛
- دفتر callback؛
- Excel؛
- sticky note؛
- status سؤال‌محور؛
- مدیر همه‌چیز را در ذهن نگه می‌دارد.

## Customer Thought
«همه کلینیک‌ها همین‌طورند.»

## Marketing Job
نام‌گذاری مشکل.

### Content
- نشانه‌های workflow chaos؛
- هزینه missed follow-up؛
- checklist ارزیابی عملیات کلینیک؛
- "چند کار کلینیک فقط در ذهن کارکنان است؟"

## Exit Criteria
مشتری بگوید:
**«بله، این مشکل را داریم و ارزش بررسی دارد.»**

# 4. Stage 1 — Trigger

Trigger باعث می‌شود Pain از قابل تحمل به urgent تبدیل شود.

## Triggerهای اصلی
- شکایت بیمار؛
- درمان از دست‌رفته؛
- missed follow-up؛
- ترک پذیرش؛
- استخدام مدیر؛
- شعبه دوم؛
- افزایش تبلیغات؛
- اضافه شدن پزشک؛
- workload بالا؛
- اجرای service line جدید.

## Sales Signal
Lead باید با trigger score شود.

## سوال Discovery
«چه اتفاقی افتاد که الان دنبال تغییر هستید؟»

## Exit Criteria
یک trigger واقعی و timeline برای اقدام وجود دارد.

---

# 5. Stage 2 — Problem Awareness

## Customer Thought
«مشکل فقط آدم‌ها نیستند؛ فرآیند ما ساختار ندارد.»

## Buyer Questions
- چند کار گم می‌شود؟
- چرا مدیر باید همه چیز را پیگیری کند؟
- چرا نرم‌افزار فعلی حل نکرده؟
- آیا باید CRM بخریم؟
- آیا مشکل training است؟

## Sales Job
Problem diagnosis، نه feature pitch.

## Artifact
**Workflow Map فعلی**

مثال:

Patient Consultation  
→ Reception note  
→ Coordinator callback  
→ No answer  
→ Reminder in personal phone  
→ Lost

## Exit Criteria
Pain مشخص، owner مشخص و workflow مشکل‌دار مشخص شده باشد.

## Exit Criteria
Buyer category را درک کند و replacement anxiety کاهش یابد.

## Questions

- چقدر setup لازم دارد؟
- روی موبایل ساده است؟
- آیا با workflow ما می‌خورد؟
- امنیت چطور است؟
- قیمت چیست؟
- آیا integration لازم است؟

## Demo Strategy

Demo عمومی ممنوع.

Demo باید از workflow خود مشتری استفاده کند.

### Example Demo
1. بیمار consultation شده؛
2. task follow-up ساخته می‌شود؛
3. coordinator owner؛
4. due tomorrow؛
5. reminder؛
6. no response → re-schedule؛

## Proof Needed

- visibility؛
- audit؛
- low doctor friction.

## Exit Criteria

**«این را روی workflow خودمان امتحان کنیم.»**

# 8. Stage 5 — Technical & Risk Evaluation

## Security Questions
- داده کجا ذخیره می‌شود؟
- چه کسی دسترسی دارد؟
- roleها چیست؟
- audit داریم؟
- backup؟
- حذف داده؟
- اطلاعات حساس بیمار چه می‌شود؟

## Operational Questions
- downtime؟
- support؟
- onboarding؟
- اگر کارمند جدید آمد؟
- Telegram account requirement؟

## Integration Questions
- PMS چیست؟
- export/API؟
- calendar؟
- SMS/WhatsApp؟
- existing patient ID؟

## Product Response
در فاز اولیه:
- minimum necessary patient data؛
- role-based access؛
- audit trail؛
- clear data boundary؛
- avoid clinical decision storage unless designed for it.

## Exit Criteria
هیچ blocker امنیتی/فنی حل‌نشده‌ای که Pilot را غیرممکن کند باقی نماند.

# 9. Stage 6 — Business Case

## Buyer Needs
مالک باید بداند چرا این پروژه ارزش پول و تغییر دارد.

## ROI Inputs

### Time
- ساعت coordination؛
- time spent status chasing؛
- manual callback management.

### Leakage
- missed follow-up؛
- treatment opportunity؛
- reactivation.

### Management
- reporting time؛
- dependency risk.

## ROI Formula نمونه

**Monthly Value = Time Saved + Recovered Opportunity Value + Reduced Operational Error Value**

در Sales نباید recovered revenue بدون baseline تضمین شود.

## Business Case Output
یک صفحه شامل:
- current pain؛
- 2 workflow؛
- baseline؛
- target outcome؛
- Pilot cost؛
- success criteria.

## Exit Criteria
Economic Buyer Pilot را از نظر اقتصادی منطقی بداند.

# 10. Stage 7 — Decision

## Decision Criteria احتمالی

به ترتیب اهمیت برای ICP:

1. ease of adoption؛
2. workflow fit؛
3. owner visibility؛
4. implementation effort؛
5. security/privacy؛
6. integration؛
7. price؛
8. AI.

نکته:
AI احتمالاً دلیل اصلی خرید نیست. AI باید adoption و speed را بهتر کند.

## Common Objections

### «نرم‌افزار داریم»
پاسخ: gap بین record system و execution workflow را نشان بده.

### «تیم استفاده نمی‌کند»
پاسخ: Pilot محدود + Telegram-first + adoption metric.

### «گرانه»
پاسخ: ROI را با pain واقعی مقایسه کن.

### «وقت setup نداریم»
پاسخ: done-with-you template setup.

### «اطلاعات بیمار حساس است»
پاسخ: scope، minimum data و controls را شفاف کن.

## Exit Criteria
- sponsor؛
- scope؛
- users؛
- start date؛
- success metric؛
- commercial terms.

# 14. Stage 11 — Adoption

## Adoption Curve

### Frontline
Capture → Complete → Trust reminders.

### Manager
Assign → Review overdue → Use dashboard.

### Owner
Weekly dashboard → trend → decision.

## Adoption Signals
- tasks created without manager prompting؛
- templates reused؛
- comments/context داخل سیستم؛
- dashboard viewed weekly؛
- fewer manual status requests.

## Anti-Signal
تمام taskها توسط یک admin وارد می‌شوند و کاربران فقط passive هستند.
